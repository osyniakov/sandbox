# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo shape

Two-tier app in a single repo:

- `backend/` — Spring Boot 3.3 / Java 21, Maven (`pom.xml`, `./mvnw`). Source under `src/main/java/com/example/bpmn/`. H2 in-memory DB; data resets on every restart.
- `frontend/` — Angular 18 standalone components, npm. `src/app/features/{diagram-list,modeler,viewer}` are the routed screens; `src/app/core/diagram.service.ts` is the only API client.
- `docs/screenshots/` — referenced by the PR description; regenerated by `frontend/scripts/take-screenshots.mjs`.

There is no `npm` / `mvn` workspace glue between them. Each side is built independently.

## Common commands

Backend (`cd backend`):

```bash
./mvnw spring-boot:run            # dev server on :8080, H2 console at /h2-console
./mvnw test                       # one @SpringBootTest: DiagramControllerTest (full CRUD)
./mvnw -Dtest=DiagramControllerTest#crudHappyPath test   # single test
./mvnw -Pprod clean package       # bundles Angular into the fat jar (see "Prod bundle" below)
```

Frontend (`cd frontend`):

```bash
npm start                         # ng serve on :4200, proxies /api -> :8080 via proxy.conf.json
npm run build                     # production build to dist/bpmn-app/browser/
npm run e2e                       # Playwright (spawns BOTH dev servers via webServer)
npm run e2e -- diagrams.spec.ts -g "properties panel"   # single test by grep
npm run e2e:ui                    # interactive Playwright UI
node scripts/take-screenshots.mjs # regenerates docs/screenshots — requires both dev servers running
```

## Architecture you can't see from one file

### Prod bundling

`backend/pom.xml` has a `prod` profile that uses `frontend-maven-plugin` to download Node, run `npm install` + `npm run build`, and then `maven-resources-plugin` copies `frontend/dist/bpmn-app/browser/` into the jar's `static/`. The default Maven build skips all of that for fast backend iteration. `backend/src/main/resources/static/` is gitignored except for `.gitkeep`.

### SPA deep links

`com.example.bpmn.web.SpaForwardingController` forwards `/`, `/diagrams`, and `/diagrams/**` to `forward:/index.html` so deep links work in the prod jar. If you add new top-level routes in `frontend/src/app/app.routes.ts`, mirror them in this controller's `@GetMapping`.

### bpmn-js integration

- The modeler is instantiated in `ModelerComponent.ngAfterViewInit` with `additionalModules: [BpmnPropertiesPanelModule, BpmnPropertiesProviderModule]` and `propertiesPanel: { parent: <host div> }`. Editing the panel mutates the diagram's businessObject; nothing extra to wire.
- The viewer uses `NavigatedViewer` (read-only). It cannot host the properties panel — that needs the modeling primitives.
- `bpmn-js` has no `@types/bpmn-js` package. Types come from `frontend/src/types/bpmn-js.d.ts` (a hand-rolled shim). Extend that file when you call new methods or pass new constructor options. The `bpmn-js-properties-panel` shim there is intentionally `unknown` — the modules are opaque tokens for bpmn-js' DI.
- Stylesheets live in `angular.json` `styles[]` (both `build` and `test` arrays). `bpmn-js-properties-panel` v5+ does NOT ship its own CSS; only `@bpmn-io/properties-panel/dist/assets/properties-panel.css` is needed.

### Routing quirks worth knowing

- `/diagrams/new` and `/diagrams/:id/edit` both load `ModelerComponent`, but they are separate `Route` entries, so Angular **destroys and recreates** the component when you navigate between them. Any in-component state set right before the navigation (e.g. the "Saved at …" status banner) is lost.
- Creating a new diagram from `/diagrams/new` calls `router.navigate(['/diagrams', id, 'edit'], { replaceUrl: true })` after POST — by design, so a reload of the post-save URL re-loads the persisted XML.

### E2E test conventions

- `frontend/e2e/diagrams.spec.ts` uses `data-testid` selectors only — keep adding them when you build new UI rather than CSS-class selectors.
- Tests run sequentially (`workers: 1`); they share one Spring Boot instance and each test calls `clearAllDiagrams(request)` in `beforeEach`. Seed via `seedDiagram(request, name, xml?)` from `frontend/e2e/fixtures.ts`.
- `playwright.config.ts` spawns the backend with `cwd: '../backend'` so `./mvnw` finds the pom. Don't change the cwd without also adjusting the command.
- `@playwright/test` is pinned to `^1.56.x` because the sandbox image ships chromium-1194; bumping Playwright will fail with "Executable doesn't exist" unless the browser is re-installed. See the README "Tests" note.

### REST surface

All under `/api/diagrams`, handled by `DiagramController`. The full contract is in the README. Two DTO shapes:

- `DiagramSummary` (list view) — no `xml` field
- `Diagram` / `DiagramResponse` (single fetch / create / update) — includes `xml`

`DiagramService.findById` throws `DiagramNotFoundException` (mapped to 404 via `@ResponseStatus`). There is no global `@ControllerAdvice` yet — add one if you need richer error bodies.

### Sample-diagram seeding

`SampleDiagramSeeder` (`ApplicationRunner`) loads every `*.bpmn` under `backend/src/main/resources/sample-diagrams/` on startup, **only when the `diagram` table is empty**. The seeder is gated by `app.seed.enabled` (default `true`, `matchIfMissing = true`); set `app.seed.enabled=false` (env: `APP_SEED_ENABLED=false`) to disable it. Filename order controls list position; the leading `^\d+-` prefix is stripped and hyphens become spaces to build the display name. Backend tests that assert an empty list must set `@SpringBootTest(properties = "app.seed.enabled=false")` (see `DiagramControllerTest`). The Playwright suite is unaffected — `clearAllDiagrams` in `beforeEach` wipes the seeded rows.

## Conventions

- New tests get a `data-testid` on the element they target.
- New screens go under `frontend/src/app/features/<name>/` as standalone components, with lazy `loadComponent` routes in `app.routes.ts`.
- Don't edit `backend/src/main/resources/static/` — it's the Maven copy target for the production frontend bundle.
